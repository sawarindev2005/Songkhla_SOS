# Songkhla SOS

- `client/` is Next 16.4 / React 19; read `client/AGENTS.md` before UI changes. `server/` is Express 5 with MySQL through `server/src/db.js`. Existing API startup: `node src/index.js` from `server`; client verification: `npm.cmd run lint` and `npm.cmd run build` from `client`.
- Preserve local edits when checking upstream work; do not overwrite whole files with upstream versions. Independent local preview copies are not deployed or merged code.

## Rescuer applications and upstream integration

- Public `/register` submits rescuer applications; command/admin review them at `/command/applications`. `StaffShell` polls the pending count while preserving the shared guarded logout and toast behavior. Admin account editors normalize comma-separated equipment into checkbox arrays before capturing their unsaved-form snapshot.
- `server/sql/schema.sql` is the only SQL file: it defines all six tables, including `users.team_size`, `users.equipment`, `users.service_area`, `rescuer_applications`, and `public_announcements`. There are no separate migration files.

## Admin-authored announcements

- `server/src/routes/announcements.js` exports `announcementRouter(db)` for real SQL use and isolated HTTP tests. The public route is `GET /api/announcements/public`; all other announcement routes require the existing JWT cookie and **admin** role. Command/rescuer accounts cannot read drafts or write announcements.
- Storage is `public_announcements`; its `created_by` foreign key references `users.id`. Public queries filter `is_published = 1`, use `no-store`, and return up to 50 announcements by publication time. New records default hidden; publishing is explicit. Content is plain text, not HTML.
- **Never run `server/sql/schema.sql` over existing data without the user's approval and a backup:** that file drops and recreates the entire database.
- `/admin/announcements` uses the shared guarded Modal, validation focus, confirmation, toast, and retry components. Publish/hide uses a native checkbox with `role="switch"` on each list card: left/gray hides and right/blue publishes. The 44px label target supports click and native Space activation, shows keyboard focus, respects reduced motion, and stays disabled while saving. Saving the content editor must not change publication state. `/`, `/shelters`, and `/distributions` poll the public endpoint every 15 seconds, combine authored announcements with existing automatic place messages, and display both in `NewsTicker`. A failed authored feed leaves automatic place messages available.
- Check `node --test src/routes/announcements.test.js` from `server` and `node --test src/lib/published-announcements.test.mjs` from `client`, plus client lint/build. HTTP tests use an in-memory SQL adapter and never migrate or write the project database. This is not evidence that a migration has been applied or tested on real MySQL.
- For an approved existing-database migration, verify the configured database identity and `users.id` type first, save a restricted-access backup outside Git, and compare existing table data and definitions before/after. Real MySQL CRUD verification can inject one transaction-bound connection into `announcementRouter(connection)` and roll back in `finally`; never inject the pool for a rollback-only test, because pooled statements may use different connections. A temporary preview using an in-memory adapter does not verify persistence; connect its announcement route to the configured database before offering real-data testing.
- Publication switches display the requested state immediately, roll back on a failed PATCH, and merge the confirmed response into the polling cache with `usePolling.updateData`. That method cancels older reads; `polling-data.mjs` guards stale commits. Keep pending control dimensions fixed and avoid fading all cards. Verify cache races with `node --test src/lib/polling-data.test.mjs` from `client`, and delayed-request geometry in the browser.
- `Button.pending` interlocks a button with native `disabled` and `aria-busy` while retaining its normal variant, border, dimensions and text. Announcement write/edit/delete actions use it during publication saves; ordinary `disabled`/`loading` styling is unchanged. Check background/text/border colors as well as geometry before, during and after a delayed PATCH, including a failure and 320px layout; otherwise disabled gray flashes can survive a geometry-only check.
