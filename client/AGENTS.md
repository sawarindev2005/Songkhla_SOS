## Form focus and mobile keyboards

- The global `:focus-visible` fallback belongs in Tailwind's `base` layer so component focus utilities can override it. `TextField` and `SearchField` outline their wrapper once; do not add a second outline to their inner input.
- Root `FormViewport` observes editable focus, window resize, and `visualViewport` changes below 1024px. When a keyboard reduces visible height by more than 100px, it preserves the public shell's pre-keyboard height and bottom navigation position, pins the shell against document scrolling, and shrinks only `data-form-main` inside a full-height reserved content slot. The keyboard covers the navbar at its original bottom edge; never resize the entire shell to the visual viewport or raise the navbar above the keyboard. Existing form scrollers reveal the active control and its label when both fit, while shared form modals fit the visible height. Desktop and pinch zoom keep native panning. A short settling check follows native focus/resize scrolling and is cancelled by a new pointer interaction, wheel, or touch scroll. Ordinary viewport panning must not pull an old field back into view.
- `data-form-control` marks a wrapper whose outline should remain visible. `data-form-occluder` marks the protruding SOS circle so form scrolling leaves clearance above it; these attributes do not change navigation styling. Open native dialogs ignore page overlays and keep background scrolling inert. Modal headers and footers stay outside their shrinking scroll body.
- Below 500px of visible height on phones, `data-form-short` lets map sheets containing a search input use the full available height, hide the floating toolbar, and compact their header. The drag handle and heading remain available. Normal-height sheets and place details keep their existing layout. This avoids toolbar/header content pushing search below the keyboard; verify both search sheets before and after restoring height.
- The viewport metadata requests `interactive-widget=resizes-visual` for supporting browsers. The shell-height fallback also preserves the navbar position if the browser resizes the layout viewport. Keep the keyboard geometry until visible height is restored after blur, and keep user zoom enabled. Public fields must scroll their own containers rather than the document so focus scrolling cannot lift the navbar.
- Verify `node --test src/lib/form-viewport.test.mjs`, targeted ESLint, and `npm run build` from `client`. Check request text/tel/textarea/address, login username/password, account forms, shelter/distribution forms including number/time/select, and search fields. Exercise tap, Next/Tab, manual scrolling, opening/closing modals, shrinking and restoring height, and desktop focus. Check a 320px phone with about 268px remaining height and a 390px phone with 360px remaining height. Edge viewport resizing is a simulation; verify the actual OS keyboard on iOS and Android before claiming device keyboard coverage.

## Staff form and loading states

- `AuthProvider.logout` clears the client user only after `/auth/logout` succeeds. Both staff shells use `useLogout`: prevent duplicate clicks, await success before navigating, and show an error on the current page if logout fails. Do not swallow logout errors or redirect optimistically.
- Account and place modals pass `busy={saving}` to `Modal`, disable the form fieldset and footer cancel button, and keep errors and entered values visible after a failed save. A busy modal blocks its close button and Escape; the place picker is inert during saving. `ConfirmDialog` also blocks cancellation while its action is loading.
- `src/lib/place-validation.mjs` validates shelter capacity and current occupancy as whole numbers from 0 through the signed MySQL INT maximum. `PlaceManager` sends these as numbers so valid exponent/decimal notation is not truncated by server `parseInt`. Distribution forms keep their existing validation. Do not infer that occupancy must be below capacity; overcrowding can be recorded.
- Render empty lists only after a successful load. Public place lists, place management, assignment, and rescuer pages keep load errors distinct from empty data. Counts use `—` before data is available; a failed refresh may keep previous successful data with its error banner.
- Verification: `node --test src/lib/form-viewport.test.mjs src/lib/place-validation.test.mjs`, `npm run lint`, and `npm run build` from `client`. In a dedicated browser tab, intercept API responses to check failed logout, pending save/Escape, failed save retaining the form, invalid shelter counts sending no mutation request, and failed initial loads versus successful empty lists. Never send test create/update/delete requests through to real records.

## Unsaved forms and unexpected errors

- Account/place editors capture `formSnapshot` at open. `Modal` receives `dirty`; its close button, Escape and footer cancellation request a discard confirmation only when editable values or map coordinates differ. Use the modal footer render function's `requestClose` for cancellation. Returning to editing preserves values and focus; discarding closes the form. Unchanged/reverted values close immediately. Dirty modals also register the browser's standard `beforeunload` warning; this is not an in-app navigation blocker. Never persist password drafts to storage.
- `ErrorBanner` awaits its retry callback, displays a disabled `กำลังลองใหม่…` control, and prevents repeat clicks until completion. Combined retries must return `Promise.all` for all failed GET sources. Keep `usePolling.refresh` restart semantics after successful writes; Retry must not replay writes. Public place lists use the same banner.
- `app/error.js` uses `PageError` for unexpected rendering failures, with Thai recovery actions and no raw exception details. `app/global-error.js` supplies its own Thai document and inline styling if the root layout fails. Next 16.4's error boundary prop is `retry`; use it for route re-fetching and recovery.
- Verification also includes `node --test src/lib/form-snapshot.test.mjs`. Browser checks: clean/dirty/reverted forms, close/X/Escape, cancel/discard and map-only changes, pending save bypassing no guards, delayed/failed/successful GET retries, and a malformed mocked API response that throws during rendering followed by successful boundary retry. Do not add a production crash-test route or send test mutations to the database.
